# Patient Zero — объяснение всего проекта и каждого файла

## 1. Зачем нужен проект

Мы работаем как аналитик лаборатории: сравниваем старый и новый штаммы вируса, ищем ген в геноме, проверяем, какие фрагменты сохранились, и выбираем людей для тестирования. ДНК представлена строками из символов `A`, `C`, `G`, `T`. Все ответы вычисляются по входным файлам — никаких заранее вписанных результатов.

**Девять выводимых строк:** `Mutations`, `Shared core`, `Marker hits`, `First hit`, `Border length`, `Shared words`, `Tests needed`, `Cheapest testing`, `Longest chain`.

**Правило курса:** исходники на Java 17+, готовые методы поиска подстроки и сторонние библиотеки поиска не используются для миссий. `Main.java` и остальные системные классы из starter-проекта остаются неизменными.

### `src/Main.java`

Это **точка входа** программы: `public static void main(String[] args)`. Без аргументов читает папку `data`, с четырьмя аргументами читает переданные пути: strains, genome, markers, tree. Последовательно вызывает `Strains`, `Marker`, `Outbreak`, печатает 9 строк, затем вызывает `Render.page(...)` и создаёт `output/outbreak.html`. Константа `WORD = 12` — длина слова для Rabin-Karp. Файл оставлен как в starter-проекте.

### `src/Input.java`

Отвечает за чтение данных. Три `record`: `Strains(a,b)`, `Markers(marker,panel)`, `Tree(n,a,b,cost)`; методы `readStrains`, `readGenome`, `readMarkers`, `readTree` читают соответствующие файлы. `Tree.neighbours()` превращает недиректированные рёбра в списки соседей (`int[][]`), необходимые для DFS. В `Input` применяется `split()` только для **разбора файла**, а не для поиска ДНК-подстроки в миссиях.

### `src/Strains.java`: Миссии 1 и 2

**Миссия 1 — `editDistance(String a, String b)`**. Строится таблица `d` размером `(n+1) × (m+1)`, где `d[i][j]` — минимальное число операций, чтобы превратить первые `i` букв A в первые `j` букв B. Начальные условия: `d[i][0] = i` (удалить всё) и `d[0][j] = j` (вставить всё). Для каждой пары `(i,j)` берём минимум из трёх вариантов:

```text
delete  = d[i-1][j] + 1
insert  = d[i][j-1] + 1
replace = d[i-1][j-1] + (a[i-1] == b[j-1] ? 0 : 1)
d[i][j] = min(delete, insert, replace)
```

Возвращается `d[n][m]`. Если `A = "ACGT"` и `B = "AGT"`, достаточно удалить `C`, значит результат **1**. Время O(nm), память O(nm).

**Миссия 2 — `lcsLength(String a, String b)`**. Таблица того же размера, но смысл другой: `d[i][j]` — длина наибольшей общей подпоследовательности первых `i` и `j` букв. Если последние буквы равны — `d[i-1][j-1] + 1`; если не равны — `max(d[i-1][j], d[i][j-1])`. Сначала всё заполнено нулями. В отличие от **substring**, подпоследовательность разрешает пропускать буквы. Пример: у `ACGTT` и `AGTC` общая подпоследовательность `AGT` длиной **3**. Время O(nm), память O(nm).

### `src/Marker.java`: Миссии 3 и 4

**Миссия 3a — `prefixFunction(String p)`**. Массив `pi[i]` хранит длину самого длинного собственного префикса строки `p[0..i]`, который одновременно совпадает с её суффиксом. `matched = pi[i-1]`: при несовпадении прыгаем к `pi[matched-1]`, а если символ совпал — увеличиваем `matched`. Например, для `ACGAC` получится `[0,0,0,1,2]`; `Border length` равен последнему элементу, **2**. Сложность O(m), память O(m).

**Миссия 3b — `findAll(String text, String p)`**. Это **KMP**: один указатель `i` последовательно идёт по геному, а переменная `matched` показывает число совпавших букв шаблона. Если буквы различаются, откат идёт **по массиву `pi`**, но `i` назад не возвращается. Когда `matched == p.length()`, позиция начала совпадения — `i - p.length() + 1`. После полного совпадения вместо обнуления делается `matched = pi[matched-1]` — так сохраняются **перекрывающиеся** вхождения (например, `AA` в `AAAA` начинается в 0, 1 и 2). Ответ — массив стартовых индексов. `Marker hits` — длина массива, `First hit` — первый элемент либо `-1`. Время O(n+m), память O(m + число совпадений).

**Миссия 4 — `sharedWords(String a, String b, int k)`**. Метод считает **количество стартовых позиций в A**, для которых фрагмент длины `k` где-нибудь встречается в B. В `Main` длина `k=12`. Это **Rabin-Karp с rolling hash**: сначала хешируем все окна B и запоминаем их позиции в `HashMap<Long, List<Integer>>`; затем сканируем окна A. Хеш после сдвига окна вычисляется за O(1), а при равных хешах символы всегда сравниваются вручную, потому что возможны коллизии.

```text
HASH = (HASH * BASE + code(char)) % MOD
newHash = ((oldHash - code(out) * BASE^(k-1)) * BASE + code(in)) % MOD
BASE = 257; MOD = 1_000_000_007
```

В коде вычисление вынесено в `firstHash(...)` и `roll(...)`, а окончательная проверка — в `sameWindow(...)`. Если одинаковое слово встречается в A два раза, считать нужно **2 позиции**; после первого подтверждённого совпадения данного окна цикл кандидатов прерывается, чтобы позицию A не посчитали дважды. Если окно слишком длинное для любой строки — ответ 0. Средняя стоимость близка к O(n+m), но много кандидатов с одинаковым хешем могут дать O(nmk) в худшем случае. `HashMap` — разрешённая стандартная коллекция; запрещённый готовый строковый поиск не применяется.

### `src/Outbreak.java`: Миссия 5

Дерево заражений задано **без направления**; логически делаем человека `0` корнем. В обходе DFS аргумент `parent` нужен, чтобы по недиректированному ребру не вернуться назад.

**`cheapestTests(int n, int[][] nb, int[] cost)`** решает задачу минимального **вершинного покрытия дерева**: для каждого ребра `(u,v)` хотя бы один конец должен быть выбран для теста. Для каждой вершины `v` хранятся два числа:

```text
include[v] = cost[v] + Σ min(include[child], exclude[child])
exclude[v] =           Σ include[child]
```

Состояние `include` означает «проверяем v», поэтому дети могут быть любыми; `exclude` означает «не проверяем v», поэтому **все дети обязательно должны быть проверены**. Метод `computeCosts(...)` считает значения снизу вверх. Метод `rebuildTests(...)` идёт сверху вниз и возвращает массив `boolean[] tested`, потому что визуализатор должен знать **конкретных выбранных людей**, а не только сумму. `Main` вызывает один и тот же метод дважды: с ценой **1 каждому** для `Tests needed` и с **реальными ценами** для `Cheapest testing`. Время O(v), память O(v).

**`longestChain(int n, int[][] nb)`** находит диаметр дерева — максимальное количество рёбер в одном простом пути. `findDepth(...)` вычисляет **две** самые глубокие ветви каждого человека: `deepest` и `second`. Лучший путь через этот узел имеет длину `deepest + second`, и максимум по всем узлам — ответ. На дереве-цепочке `0-1-2-3` результат **3**; на звезде с центром 0 и тремя листьями — **2**. Время O(v), память O(h) на рекурсию.

### `src/Render.java` и `src/lab.html`

`Render.java` берёт данные алгоритмов, сериализует их в JSON-подобный фрагмент (без сторонних библиотек) и вставляет в HTML-шаблон `src/lab.html`. Готовая HTML-панель **самостоятельно пересчитывает ответы**, сравнивает ваши 9 чисел с эталоном и рисует анимации алгоритмов; показывать правильные числа заранее она не обязана. Панель полезна как средство самостоятельной отладки. Для запуска достаточно `java -cp out Main` и открытия `output/outbreak.html` в браузере.

### `src/Bench.java` и `src/Generator.java`

`Bench.java` сравнивает обычный наивный поиск с KMP на специально неудобных строках `AAAA…AAB` против `AAAA…AAA`, а также измеряет `editDistance` на случайных строках длины 500, 1000, 2000 и 4000. Каждая строка теста усредняется по 3 измерениям в миллисекундах. `Generator.java` создаёт тестовую ДНК из A/C/G/T на основе `Random`; она **не** используется для персонального варианта и не меняет результаты алгоритмов.

### `tools/MakeVariant.java`

По введённому ID детерминированно генерирует `data/strains.txt`, `genome.txt`, `markers.txt` и `tree.txt`. У двух студентов разные ID дают разные входные последовательности и ответы. Именно поэтому приведённые в архиве данные **DEMO** надо заменить собственными по команде из `START_HERE.md`.

### `tools/Check.java` и `tools/ExtraTests.java`

`Check.java` — предоставленная преподавателем проверка: **сама компилирует** исходники и сравнивает 9 строк с `expected.txt` для `tiny`, `small`, `dense`. Команда: `java tools/Check.java`. Дополнительный (не обязательный по условию) `ExtraTests.java` проверяет пустые строки, перекрытия и повторы, затем небольшие случайные строки и деревья: ответы сопоставляются с простыми независимыми реализациями, включая перебор всех множеств тестируемых людей на маленьком дереве. Команды: `javac -cp out -d out tools/ExtraTests.java`, затем `java -cp out ExtraTests`.

### Папки `data`, `examples`, `output`, `docs` и файлы в корне

`data/` — **персональные входные данные** для `Main`, сейчас в архиве демонстрационный ID `DEMO`. `examples/` — три стандартных теста и их эталонные ответы `expected.txt`. `output/outbreak.html` и `output/outbreak.png` — созданные результаты и скриншот (после подстановки своего ID пересоздай оба). `README.md` — обязательный отчёт и ссылка на скриншот. `START_HERE.md`, `docs/Assignment4.pdf`, `docs/Assignment4_defense_prep.pdf`, `docs/Hints.md` — неизменённые материалы курса. `.gitignore` не даёт случайно закоммитить скомпилированные `.class` в папке `out/`.

## 4. Самое важное для защиты

1. **Почему DP?** Ответ для длинных префиксов/поддеревьев строится из меньших оптимальных решений, которые повторно используются.
2. **Edit distance и LCS — одно и то же?** Нет. Edit distance **минимизирует число операций**, LCS **максимизирует длину упорядоченного совпадения**.
3. **Что такое pi в KMP?** Длина совпавших префикса и суффикса для каждого префикса шаблона. Она позволяет отказаться от повторного просмотра символов генома.
4. **Зачем после совпадения KMP использовать pi, а не 0?** Чтобы не терять пересечения: `AAA` в `AAAA` встречается 2 раза.
5. **Хеши Rabin-Karp совпали — можно засчитать?** Нет. Из-за коллизий надо сравнить буквы, а не только числа.
6. **Зачем в дерево передаётся parent?** Связи неориентированные, иначе DFS уйдёт назад по ребру и зациклится.
7. **Чем отличается include от exclude?** При include дети свободны выбрать минимум, при exclude каждый ребёнок обязан быть include.
8. **Почему greedy неверен?** Локально выгодная вершина не обязательно даёт минимальную глобальную стоимость для всех рёбер.
9. **Что такое диаметр дерева?** Самый длинный путь между двумя вершинами, измеренный числом рёбер.
10. **Сложности?** Edit/LCS — O(nm), KMP — O(n+m), Rabin-Karp обычно около линейной при редких совпадениях хешей, DP дерева и диаметр — O(v).
